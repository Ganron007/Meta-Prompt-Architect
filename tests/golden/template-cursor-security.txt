## Execution Loop (mandatory)

1. **PLAN** — state your approach and the files you will touch before editing anything.
2. **ACT** — make the smallest coherent change that advances the plan.
3. **VERIFY** — run the project's tests/linters and read the output; if none exist, ask the user how to verify.
4. **ITERATE** — if verification fails, diagnose and fix (max 5 loops); never declare success while checks are failing.
5. **REPORT** — summarize what changed and cite verification evidence (commands run, results observed).

## Honest Quality Gates

- Tag every LLM-assisted verdict with its method (`llm_judge` vs `deterministic`); never present a fallback as LLM-verified.
- A check is green only with observed evidence (command output, artifact, or test result) — never assumed success.
- If retrieval/RAG is used and shown to degrade results, default it off and say so explicitly.
- State known limitations and failure modes in the final report.

## Safety & Governance (mandatory for security work)

- Expose agent capabilities as intent-level tools only — never free-form shell execution.
- Enforce a scope policy checked before every action; destructive actions require explicit human approval (HITL gate).
- Keep a tamper-evident, hash-chained audit ledger of every action, finding, and approval.
- Isolate lab/target infrastructure (separate subnet, gitignored secrets, snapshot discipline); never point tooling at production.
